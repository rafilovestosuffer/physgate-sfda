\subsection{The paired leaky/clean design}

For the ten random splits, a source bearing set of 3 healthy, 3 outer-race and 3 inner-race specimens is trained at one operating condition. The
resulting source model is then adapted, without target labels, to two different targets at the same target condition
(Fig.~\ref{fig:design}): the \emph{leaky} (seen-bearing) target, made of the same physical bearings, and the \emph{clean} (unseen-bearing)
target, made of the complementary bearings. Operating condition, window length, number of windows per class, class balance, optimiser,
schedule and seed are held fixed, as in the fixed-training designs of Vieira et al.\ \cite{vieira2026}. The leaky--clean
difference, written $\Delta_{\mathrm{leak}}$, therefore measures bearing overlap \emph{together with} the difference between
the two bearing sets, which hold different specimens. Two further contrasts, both added post hoc, help characterise these components. The \emph{source-only}
difference is the same contrast for the source model before any adaptation step, read from the batch-0 accuracy that
every adaptation log records; it shows whether adaptation creates, amplifies or repairs the gap. The \emph{within-bearing}
contrast uses the ten random splits, in which every bearing is in the source in some splits and in the clean target in
others: for each bearing, its accuracy when seen minus its accuracy when unseen holds the specimen fixed. With three
conditions there are six ordered condition pairs, hence six tasks per split and per direction.

Windows are 2048 samples with 2000 windows per class; no window crosses a recording boundary. Within each recording the
windows start at evenly spaced positions and do not overlap. The window length and the count per class are those of SDALR
\cite{sdalr2025}, which states neither a hop nor start positions; its preprocessed archive was not used, so the hop is our
choice. Balance is per class, not per bearing. A class with three bearings holds 680, 660 and 660 windows, 33 or 34 per
recording of about 256\,800 samples (a hop of about 7\,700--7\,900 samples). A class with two bearings holds 1000 windows
from each, 50 per recording (a hop of about 5\,200 samples): this is the outer-race class of fold~B (KA22, KA30), as source
or as target, and of the bearing-disjoint target of every random split, because the real-damage pool holds five outer-race
bearings. For the window-based comparisons, every target holds the same number of
windows per class, so window accuracy equals balanced accuracy (the mean of the per-class recalls), so a three-class model
that ignores its input scores \SI{33.3}{\percent}.

\subsection{Splits}

\input{tables/t2_splits}

Two families of splits are used on Paderborn (Table~\ref{tab:splits}). The two \emph{mechanical folds} follow a fixed rule:
within each (damage origin, fault type) group, bearing codes are sorted lexicographically and the first half is assigned to
fold A. The folds are run in both directions, which gives 12 paired tasks. To extend beyond the two mechanical folds, we drew ten source sets uniformly without replacement from the 4000 possible
3/3/3 sets, excluding fold A, with the seed
and the draw list committed before any of these runs. The \emph{split} is the statistical unit for the ten-split analyses;
tasks are descriptive observations within a fold, not independent replicates. Every random split therefore trains on three
distinct specimens per class and is scored on three healthy, two outer-race and three inner-race specimens it has not seen.
The number of distinct source bearings, which Vieira et al.\ find decisive for supervised transfer \cite{vieira2026}, is
held at three in every adaptation experiment and is varied from one to four only in the source-diversity curve of
Section~\ref{sec:res-mechanism}. On HUST the same construction uses bearing types: the source is three of the five types
and the clean target the other two, for six pre-specified splits.

\subsection{Adaptation variants}

SDALR is run from its released code with two checkpoint policies. \texttt{as\_released} keeps the released selection rule,
which compares target accuracy against its initial value and therefore consults target labels; \texttt{final\_checkpoint}
takes the last iterate without target labels for training or checkpoint selection (except the explicitly labelled oracle arm). All headline numbers use \texttt{final\_checkpoint};
\texttt{as\_released} is reported only as a diagnostic, first in Section~\ref{sec:res-collapse}. The architecture and training settings are listed in Supplementary~S6.

SDALR was chosen because it is a recent source-free method with a Paderborn benchmark and released code, and SHOT
\cite{liang2020shot} because it is the generic source-free comparator this literature uses and the method SDALR builds on.
The two objectives differ materially. Besides label-smoothing cross-entropy on pseudo-labels and information
maximisation, SDALR's released objective has a cohesion--repulsion term on the features of pseudo-labelled windows
(weight 1) and an entropy term for the predictions it marks unreliable. On these tasks its criterion marks a median
0.6\,\% of the target windows unreliable per pseudo-labelling round (95th percentile 3.9\,\%, in the gated runs, which
log it), so the reliability split itself changes little, while the cohesion--repulsion term stays active; the released
threshold of 0.4 is a cosine distance, the counterpart of the paper's similarity threshold of 0.6. Our SHOT
implementation uses unsmoothed cross-entropy on centroid pseudo-labels with weight 0.3 plus information maximisation,
on SDALR's backbone, data, schedule and learning rates (Supplementary~S6). A later bearing-specific method
reports higher same-bearing Paderborn accuracy than SDALR \cite{yan2026hybrid}, and another above 98\,\% on other bearing
data \cite{li2025csad}, but we found no released implementation of either and did not reimplement them from their descriptions, so the adaptation evidence here is limited to
these two methods. No hyperparameter of any arm was tuned on any target: SDALR and SHOT use SDALR's released values
(Supplementary~S6), the forests use fixed defaults stated per experiment in the protocol, and the gate operating points were
fixed before evaluation. SHOT runs from our own implementation of its objective on SDALR's backbone, data and schedule.
A first SHOT implementation returned pseudo-labels in the order of a shuffled loader pass rather than in dataset order, an indexing defect found by code audit; its outputs are retained for audit only (Supplementary~S6). Every SHOT result reported here comes from the corrected implementation, whose pseudo-label alignment is checked by a unit test, run on the ten splits from the same source checkpoints as SDALR.

\subsection{Gating and the oracle reference}

A gate returns one verdict per \emph{recording}, in $\{\text{silent},\text{inner race},\text{outer race}\}$, which every
window of that recording inherits; silence is not a healthy verdict. Inside the adaptation loop the verdict acts on SDALR's
pseudo-label step: where the gate speaks, a pseudo-label is kept only if it agrees with the verdict and is otherwise
withheld from the supervised term (the window still enters SDALR's entropy term, as SDALR's own unreliable samples do);
where the gate is silent, the method is unchanged. In Fig.~\ref{fig:design}b the gate speaks on KA04 and is silent on
KI17; both verdicts are those used in adaptation and hold for all 20 recordings of each bearing at A1. The \emph{oracle filter} replaces the verdict by the true label of each
window, keeping only correct pseudo-labels. It is a reference, not a proven bound: adaptation is non-convex, and a filter
that also withheld some correct labels could in principle do better. Like every arm, it is scored on the target windows it
adapts on, as is standard in SFDA.

All arms of a comparison (ungated, each gate and oracle) run in one job from the same source checkpoint with the same
seed; identical batch-0 accuracy in the adaptation logs is a consistency check, not a checkpoint-hash proof. Write $a_{\mathrm{leaky}}$,
$a_{\mathrm{clean}}$ and $a_{\mathrm{oracle}}$ for the ungated leaky, ungated clean and oracle-filtered clean accuracy, each
the mean over the six condition pairs of a split. The collapse is split as
\begin{equation}
\underbrace{a_{\mathrm{leaky}}-a_{\mathrm{clean}}}_{\text{total}}
=\underbrace{\left(a_{\mathrm{oracle}}-a_{\mathrm{clean}}\right)}_{\text{recovered by the oracle filter}}
+\underbrace{\left(a_{\mathrm{leaky}}-a_{\mathrm{oracle}}\right)}_{\text{not recovered}}.
\label{eq:decomp}
\end{equation}
The second term mixes what the source model carries with the difference in difficulty between the two bearing sets, and
can be negative.

\subsection{Statistics}

Effects are paired differences, summarised by medians over source folds or splits rather than over tasks that share a source checkpoint, and the inference target differs between summaries. For the ten random splits the estimand is the median effect over the 3,999 eligible 3/3/3 source sets of the fixed Paderborn pool, with the procedure and seed held fixed. Because the ten sets were drawn uniformly at random from them, the interval between the second and ninth smallest split values covers that median with probability 97.9\,\% (97.87\,\% for sampling without replacement from the 3,999 sets); these are the intervals reported for split-level medians. Seed variability is described separately, by three seeds on the two folds, and the fold experiments are descriptive. The 17 within-bearing contrasts reuse specimens and share models, and the six HUST splits were drawn from only ten possible ones, so their medians and ranges are descriptive. None of these intervals quantifies uncertainty for a population of new bearings. Percentile bootstrap intervals, which have no exact coverage guarantee for a median of ten values, are kept in Supplementary~S6 for comparison.

Exact sign-flip tests, one-sided in the pre-specified direction, with Benjamini--Hochberg and Benjamini--Yekutieli adjustments \cite{benjamini1995,benjamini2001} are given in Supplementary~S6; with ten splits the smallest attainable one-sided $p$ is $1/1024$. Because splits share bearings, the sign-symmetry assumption of these tests holds only conditionally on the pool, so conclusions rest on the paired effects and their directions and the nominal $p$-values are reported for completeness. The sign test, which needs no symmetry assumption, is exact for the median over the eligible source sets under the sampling used; where all ten split effects are positive it gives one-sided $p \le 1/1024$. Each random split was run with one seed: in benchmark studies the variance due to the data split exceeds that due to initialisation \cite{bouthillier2021}, the two folds carry three seeds each, and the between-seed range of the ungated clean fold mean (1.9--3.2 points, Section~\ref{sec:repro-jobs}) is an order of magnitude smaller than the effect studied. The protocol's original rule of five seeds per configuration was not followed: SDALR's released seed (2024) was adopted before the first paired run, and split-level variance replaced seed-level variance (Supplementary~S1).

Source-only, within-bearing, spillover, purity, coverage--gain and interval analyses, the labels given to seen and unseen bearings with the KI04/KI14 sensitivity, the leave-one-bearing-out check and the gate-override comparison with its breakdown by certifiable bearings are post-hoc and descriptive. Source-expansion and kinematic-feature studies are exploratory follow-ups whose decisions were specified before their own runs. Supplementary~S6 gives the balanced-accuracy sensitivity analysis and the Monte Carlo test details, computed from saved values.

Healthy false-acceptance counts are reported by bearing in Section~\ref{sec:res-gating} and Supplementary~S2. Bearing-bootstrap and record-binomial intervals are given in Supplementary~S6 with their assumptions. Repeated recordings from one bearing are not independent specimens, and zero observed false acceptances bound the rate only weakly: the exact one-sided 95\,\% upper limit is \SI{0.6}{\percent} per recording if the 480 recordings were independent, and \SI{39}{\percent} per bearing for 0 of 6 bearings (Supplementary~S6). Six healthy bearings provide limited evidence about new-bearing false alarms.

\subsection{Reproducibility, jobs and pre-specification}
\label{sec:repro-jobs}

Every effect here is a difference between two runs, so we measured the difference produced by no change at all: every
retained re-execution of the gating configuration (eleven arm pairs over 66 paired tasks on both folds) reproduces the
first execution to the last reported decimal. These retained reruns are numerically reproducible under their fixed seed and code path, and the
relevant null for a single comparison is the random trajectory itself, whose between-seed range for the ungated clean fold
mean is 3.2 points on fold~A and 1.9 on fold~B.

The fold experiments ran in two jobs at two code revisions: a fold job, which produced the leaky and clean arms, and a later
gating job, which produced the ungated, gated and oracle clean arms. The later revision wraps SDALR's evaluation routine to
save per-window predictions; source pretraining calls that routine on its validation loader halfway through training, and
creating the extra loader iterator advances the global random generator. From that point the source pretraining follows a
different trajectory, and the two jobs train different source checkpoints: their batch-0 target accuracy differs by up to
9.3 points on fold~A and 2.5 on fold~B, and their ungated clean fold-A means are \SI{58.4}{\percent} (fold job) and
\SI{56.8}{\percent} (gating job). Arms are therefore never compared across jobs, and Table~\ref{tab:collapse} gives each
fold one row per job. Leaky--clean contrasts come from the fold job, gated and oracle arms are compared with
the gating job's own ungated arm, and the fold-level oracle decomposition, which would need a leaky arm the gating job never
ran, is not reported. All ten random splits ran every arm in one job.

Prospective hypotheses, decision rules, arms and budgets were written into a version-controlled protocol before their corresponding runs; post-hoc analyses are identified separately. The fixed gate operating points were ($z = 10$ for the envelope rule, $\alpha = 0.05$ for the comb tests). The protocol
is a file in the project repository rather than a registry entry, so we call it pre-specification and the study was not registered; each entry carries the
commit that introduced it, every result artifact the commit that produced it, and the experimental release is archived publicly (Data availability). Results that failed their rule are reported as such, one planned remedy experiment was cut
for budget before any of its outcomes were seen, and every reported number carries a run identifier in an append-only ledger
with the retained artifact and its checksum (Supplementary~S4). Supplementary~S7 lists the REFORMS reporting items for
machine-learning-based science \cite{kapoor2024reforms} with the location of each in this paper, and the three leakage
arguments of Kapoor and Narayanan \cite{kapoor2023leakage}.
